# PHP 8.4 compatibility (issue #13, roadmap PHP-01 / PHP-02)

Status of the legacy PHP code base with respect to PHP 8.4 after the
changes on branch `fix/issue-13-php84-compat`. Scope: syntax and the
PHP 8 language-level breakages that make the code fail before any
request logic runs. Out of scope and untouched: authentication, SQL
injection, `eval` in configuration/templates (issue #14), SQL/schema,
JavaScript/CSS, UI, framework choices.

Legend: **[verified]** = reproduced with a command on this branch;
**[observed]** = read in the source, not executed; **[hypothesis]** =
plausible, not demonstrated.

Tooling used: PHP 8.4.27 (`/usr/bin/php8.4`) and PHP 8.3.6
(`/usr/bin/php8.3`), CLI only. No web server was started and no database
was contacted.

Why Services_JSON stays: all 269 model files under `dev/src/*.json` start
with a `/** ... */` banner comment (as does `dev/services/service.example.json`;
`dev/interface/forms/new_profesor.json` uses unquoted keys).
`json_decode()` rejects all 271 of them (`Syntax error`),
while the patched `Services_JSON::decode()` decodes all 269 `dev/src`
files to objects on PHP 8.4. **[verified]** Switching to native JSON would
therefore need a comment-stripping step: not a trivially equivalent
change, so it is left for a separate decision.

### 2.1 Services_JSON (vendored)

- 40 curly-brace string offsets `$s{n}` → `$s[n]` on 38 lines (parse error since 8.0),
  `sed -E 's/\$(utf16|utf8|var|chrs|str)\{([^}]*)\}/$\1[\2]/g'`; the
  word diff contains only these substitutions.
- PHP 4 constructors `Services_JSON()` / `Services_JSON_Error()` →
  `__construct()`; `parent::PEAR_Error()` → `parent::__construct()`
  (only reached if a `PEAR_Error` class is loaded, which this repository
  never does).
- A "Local modifications" note was added below the original BSD header.

### 2.2 PHP 4 style constructors (198 classes)

Since PHP 8.0 a method named like its class is an ordinary method, so
`new X(...)` silently skipped initialisation (e.g. models without `->db`,
collections without `->data`, entities with no fields).

- Rewritten by `dev/php84/rewrite-php4-constructors.php` (token based:
  only the method-name token changes, one line per class). Command:
  `git ls-files -z '*.php' '*.tpl' | xargs -0 php dev/php84/rewrite-php4-constructors.php`
- 198 renamed: 164 in `model/data`, 1 `model/data/views`, 19
  `model/security`, 4 `model/generator`, 2 `model/util`, 6
  `lib/ancora/timeutils`, `lib/basic/cli/Console`,
  `lib/basic/file/PropertiesFile` (+3 in Services_JSON, §2.1). No class
  had both forms.
- The script aborts if any legacy constructor is also called explicitly by
  its old name (`->Name(`, `::Name(`); there were none, so **no alias
  methods** were kept. **[verified]**
- Inheritance is unchanged: classes without their own constructor (e.g.
  `PersonsService extends PartModel`, whose `Persons()` method was never a
  constructor) inherit `PartModel::__construct` exactly as they inherited
  `PartModel::PartModel` on PHP 5. **[observed]**

### 2.3 Undefined constants in generated `add()` (328 expressions, 61 files)

The generated `add()` methods built INSERT values with
`(descripcion==null?'null':"'".$descripcion."'")` — the left operand
lacks its `$`. PHP 5/7 evaluated the undefined constant as the string
`'descripcion'`, so the comparison was always false and the else-branch
always ran; PHP 8 throws `Error: Undefined constant`.

- To keep the generated SQL byte-identical to the historical behaviour
  each expression is replaced by the branch that always ran:
  `("'".$descripcion."'")` for quoted columns, `($dia)` for numeric ones.
- Script: `dev/php84/rewrite-null-ternaries.php` (regex with a
  back-reference: the identifier must equal the variable name). Command:
  `git ls-files -z 'model/*.php' | xargs -0 php dev/php84/rewrite-null-ternaries.php`
  → 328 expressions in 54 `model/data`, 6 `model/security`, 1
  `model/generator` files.
- Equivalence check **[verified]**: for each of the 61 changed lines, the
  old line was evaluated with each bare identifier defined as a constant
  equal to its own name (PHP 5/7 semantics) and compared with the new line
  for 8 argument values (`null`, `''`, `0`, `'0'`, `'abc'`, `5`, `'1.5'`,
  `'true'`): 488 comparisons, 0 differences.
- **Deliberately not done:** turning this into real NULL handling
  (`$x === null ? 'null' : ...`). The roadmap's `$var == null` would be a
  behaviour change (with loose `==`, `''` and `0` would become SQL `NULL`,
  e.g. day/slot `0`). Whether missing values should become `NULL` belongs
  to SQL characterisation (#10) / generated-layer decision (PHP-08).
- Static check after the change: 0 undefined constants in the whole tree
  (not only in the targeted pattern). **[verified]**

### 2.4 Static calls to non-static methods (22 call sites)

`TimeUtils::number_to_date()`, `TimeUtils::number_to_hour()`,
`TimeUtilsCommon::date_to_number()`, `TimeUtilsCommon::hour_to_number()`
and `DirectoryUtil::getFilesWithExtension()` are called statically from
templates and handlers, including `view/custom/app.tpl` (main application
page), `form_periodo*.tpl`, `form_restricciones.tpl`,
`planificaciones.tpl`, `diagrama_gantt_planificaciones.tpl`,
`get_form_edit_Planificacion.php`, `fdm_Planificacion_fecha_inicial.php`.
PHP 5 allowed this; PHP 8 throws `Error`.

- None of these methods uses `$this`; they call each other via
  `self::`/`parent::`. The 7 `TimeUtilsCommon` methods, the 2 `TimeUtils`
  converters and `DirectoryUtil::getFilesWithExtension()` are now
  `public static`. Instance calls (`$this->date_to_number()` in `TDate`,
  `$this->hour_to_number()` in `THour`) still work.
- Equivalence **[verified]**: ~5,700 inputs through `number_to_date`,
  `number_to_hour`, `date_to_number`, `hour_to_number`, comparing the old
  files called on an instance with the new files called statically and on
  an instance: identical output (same MD5); the old files called
  statically throw `Error` on PHP 8.4.

### 2.5 Generator consistency (`dev/cogephp.php`)

The generator was changed to emit exactly what is now committed:

- every generated constructor (`PartModel`, `*Model`, `*DatabaseViews`,
  `*Collection`, entities, `*Functions`, and the not-committed
  `<Project>Control`/`<Project>Model` classes) is emitted as
  `__construct` (8 `fputs` lines);
- the `add()` value expression emits `("'".$name."'")` / `($name)`.
  Fragment check **[verified]**: the new `fputs` strings produce
  `".("'".$descripcion."'")."` and `".($dia)."`, found verbatim in
  `AsignaturaModel.php` / `ActividadModel.php`.

Not verified: a full regeneration. It needs the 2010 PostgreSQL model
database (`dev/cogephp.conf`) and would also rewrite the `@updated`
timestamps of every file, so committed files and generator output can only
be compared at the fragment level. `dev/cogephpservice.php` still emits
the historical `function <Name>($db)` (not a constructor of class
`<Name>Service`); it was left unchanged because changing it would alter
behaviour of regenerated services.

## 3. Lint and checks: commands and counts

### 3.1 `php -l` (syntax only)

`php -l` parses a file without executing it. It does **not** resolve
includes, classes, functions or constants, and it does not detect
cross-file errors (inheritance, signatures). `.tpl` files are PHP-embedded
templates `include`d by the application, so they are linted as PHP; 6 of
the 266 templates contain no PHP block and lint trivially. No short open
tags (`<?` without `php`) exist in tracked `.php`/`.tpl` files (grep), so
the result does not depend on `short_open_tag`; CI pins it `Off`.

Baseline, `origin/master` (2881353), 939 tracked `.php`+`.tpl` files:

```sh
git ls-files -z '*.php' '*.tpl' | xargs -0 -n1 -P8 sh -c \
  '/usr/bin/php8.4 -l "$0" >/dev/null 2>&1 && echo "OK $0" || echo "FAIL $0"'
```

| PHP | OK | Failed | Failing files |
| --- | --- | --- | --- |
| 8.4.27 | 935 | 4 | `lib/enterprise/nusoap/{nusoap,nusoapmime,class.soapclient}.php`, `lib/parsers/json/JSON.php` |
| 8.3.6 | 935 | 4 | same |

After (this branch), 931 tracked files (939 − 12 NuSOAP + 4 new scripts):

```sh
dev/ci/php-lint.sh                        # php from PATH
PHP=/usr/bin/php8.3 dev/ci/php-lint.sh
```

| PHP | Checked | OK | Failed | Exclusions |
| --- | --- | --- | --- | --- |
| 8.4.27 | 931 | 931 | 0 | 0 |
| 8.3.6 | 931 | 931 | 0 | 0 |

**Exclusion list: empty.** The only files that failed were removed
(NuSOAP, unreferenced) or fixed (Services_JSON). `EXCLUDES` in
`dev/ci/php-lint.sh` is kept as an explicit, documented mechanism; any
future entry must be justified here.

### 3.2 PHP 8 static check and constructor smoke test

```sh
dev/ci/php84-check.sh                     # PHP=/usr/bin/php8.3 to override
```

runs:

1. `php dev/ci/php84-static-check.php --self-test` (8 built-in cases);
2. `php dev/ci/php84-static-check.php --allow=... <all tracked .php/.tpl>`
   — token-based rules: `php4-ctor`, `const` (bare identifier that is
   neither a PHP constant nor `define`d/`const` in the scanned files),
   `removed-fn` (`each`, `ereg*`, `split`, `create_function`, `mysql_*`,
   `money_format`, `get_magic_quotes_*`, `__autoload`, ...),
   `static-call` (non-static method of a scanned class called
   statically outside a parent/self-style instance context);
3. `php dev/ci/php84-constructor-smoke.php` — declares the generated data
   layer and instantiates the 130 `PartModel` subclasses and `*Collection`
   classes with a stub connection object (no DB), asserting `->db` /
   `->data` were set by the constructor.

| Rule | `origin/master` (all 939) | `origin/master` without NuSOAP (927) | This branch (931) |
| --- | --- | --- | --- |
| php4-ctor | 220 | 201 | 0 |
| const | 330 | 328 | 0 |
| static-call | 22 | 22 | 0 |
| removed-fn | 65 | 7 (`mysql_*`) | 0 (7 allow-listed) |
| constructor smoke | — | 0 of 130 constructors run | 130 of 130 |

Allow-list (one entry): `removed-fn:lib/enterprise/gendb/MySQLDatabaseImpl.php`
— the alternative MySQL driver is only `include`d by the generator; the
calls fail only if the class is used. Removing it would break
`dev/cogephp.common.php`; isolating it is roadmap PHP-01 follow-up work.

Limits of the static check: heuristic, single-token context; it does not
resolve includes, namespaces, variable class names or dynamic calls, and it
cannot prove runtime correctness.

## 4. Remaining runtime / HTTP-level blockers (seen, not fixed)

These are outside "syntactic compatibility" or are pre-existing defects
(they fail on PHP 5 too). They are listed for PHP-03…PHP-12 and #14.

1. **`explode()` with one argument** in every generated
   `getJoinWith*ByPhrase()` (278 calls, plus `$this->fieldnames`, an
   undefined property). PHP 8: `ArgumentCountError`; PHP 5: warning and
   broken SQL. Pre-existing generator defect. **[observed]**
2. **Wrong constructor arguments in handlers** (now visible because the
   constructors exist): 61 `control/view/gallery/get_ui_gallery_*.php`
   call `new <Entity>($dbconnection)` and then `->Load()` (method of the
   *Collection*), and import paths ending in `.php` that `import()` cannot
   resolve; `control/custom/custom_set_Restricciones.php` passes 6 of 7
   required arguments and includes `../modelo/...` (directory does not
   exist). PHP 8: `ArgumentCountError`. All broken on PHP 5 as well
   (roadmap PHP-12). **[observed]**
3. **Unknown classes in generated entity `add<Child>()` helpers**: 129
   `new <Name>Class(...)` (no such classes) and 5
   `new Seguridad<Name>Collection` in `model/data`/`model/security`.
   Fatal when called, on any PHP version. **[observed]**
4. **`PartModel::getAllWithPhraseIn()`**: `$this-getAnything(...)` typo
   and a missing argument to `getWHEREPartOfSearchFrase()` (known from the
   assessment). **[observed]**
5. **Collections' `Reload()`** uses undefined `$last_offset`/`$last_limit`
   (61 files): warning, reloads without limit. Pre-existing. **[observed]**
6. **PHP 8 type strictness on request data** **[hypothesis]**: PHP 8.4
   throws `TypeError` for arithmetic on non-numeric strings (`"" + 1`,
   `"abc" * 1`) and for `count(null)` — verified in isolation, but which
   handlers receive empty/non-numeric POST fields needs HTTP-level tests.
7. **Dynamic properties** (PHP 8.2+ deprecation, e.g.
   `Services_JSON::$use`, `Console::$stdin`, ad-hoc `$item->x`): only
   `E_DEPRECATED` notices on 8.4; will become errors in PHP 9.
   **[verified]** for `Services_JSON`.
8. **Relative includes** (`include "../view/..."`, `import()`) depend on
   the working directory being `www/`; PHPStan reports 299 unresolved
   paths, most probably false positives of static resolution.
   **[hypothesis]**
9. **Security-relevant legacy code left as is** (issue #14 / PHP-03…07):
   `eval` in `PropertiesFile` and gallery templates, string-built SQL,
   MD5 passwords, session handling, `www/query.log`. Notices that PHP 5
   printed into HTTP responses (e.g. the undefined-constant notices) no
   longer occur for the fixed patterns.
10. **Not exercised at all:** a real request through `www/index.php`
    (`session_start`, `pg_connect`, `Application::Run`). The code now
    parses and the class layer constructs on 8.4, but end-to-end HTTP
    behaviour is unverified until the PostgreSQL installer (#8/#9) exists.
