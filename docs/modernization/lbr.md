# Legacy Bytes Remanufacturing: baselines and measurement (issues #38, #67, #77)

Method: [2026.014 — Legacy Bytes Remanufacturing](https://github.com/rafageist/blog-reflections/wiki/2026.014.-Legacy-Bytes-Remanufacturing). LBR is a **progress metric**. It shows how much of a fixed legacy baseline has been retired with verified evidence. It does **not** measure security, quality, effort or technical debt, which are tracked separately (#40–#62, CI test suites).

## 0. Two independent baselines (sets)

After the Drupal decision (#66) the tool measures **named sets**, each with its own commit, rules, frozen inventory and retirement records (`dev/lbr/sets/NAME/`). **Their percentages are never combined.**

| Set | Scope | Status |
| --- | --- | --- |
| `historic-2010` | First-party legacy source that already existed in the July 2010 import, measured at `eca8aa7`. It is a **historical comparator** (§1–§2 below). | frozen: B = 854,831 bytes, 572 files |
| `pre-drupal-cut` | **Comprehensive** cut (#67): every maintained first-party implementation file existing at the transition commit, including the 2026 recovery work (tests, tooling, Docker, CI, codegen), before the move into `legacy/` (#68). Excluded, with recorded reasons: the Drupal target `modern/`, docs, archival dumps, derived and generated outputs, third-party code. | **frozen at `f532e91`** (merge of PR #80, the last in-flight PR), revision 1, as a **proposal**: maintainer approval is required before #68 |

Frozen `pre-drupal-cut` at `f532e91`: **B = 4,795,406 bytes in 843 files**. C = B; retired 0. The cut commit was chosen as the merge of the last in-flight PR (#80, Divengine Codegen). The standalone portal (PR #78) is a draft outside `master`, so it is not part of the cut.

**Decision for the maintainer (approval of the cut).** The first-party images are 74 % of the comprehensive B, so retiring the old desktop's icons would dominate the completion percentage. The method allows this (byte weighting is a known limit of LBR), but the maintainer may prefer to exclude binary assets (a documented revision 2), or to keep them and read the per-stream figures.

**Relocation.** `dev/lbr/relocations.tsv` maps moved directories (for example `control/` → `legacy/control/`). A relocated file is still found at HEAD, still counted in C and listed as relocated. A retirement record for it is rejected while it exists at the new path. A move never retires anything.

Notes on the rule:
- The **origin rule** keeps the recovery work out of B. Docker, CI, tests, the SQL installer, `PasswordUtil`, `SessionUtil` and `setpassword.php` are new code, not legacy, even where they sit in legacy directories.
- Files that existed in 2010 but were rewritten during recovery stay in B at their baseline size, because their responsibility is still the legacy one. The main case is the bundler `dev/sql/compilasql.php` (#9).
- Thirteen `lib/enterprise` files and `bin/ancoragoh.conf` were removed during recovery, *before* the baseline. They are not in B and are not counted as retired.

| MPI / Prioriza (`mpi.*`) | Kept as the domain algorithm. Behaviour is fixed by `dev/sql/tests` and the E2E digest. | Only if it is reimplemented with characterization parity (not planned for R1). It stays outstanding in its own stream. |

## 4. Recording a retirement

1. In the PR that replaces or eliminates a responsibility:
   - remove the old files;
   - add a row to the set's `retirements.tsv` (one file, or a baseline directory `dir/`), with status `in-transition` until merge;
   - give the evidence: tests, E2E, security checks.
2. After review and merge, set the status to `verified`, with the PR number, the merged commit and the reviewer.
3. `php dev/lbr/lbr.php check` enforces each record:
   - the path is in the frozen baseline, and no file is covered twice;
   - every field is filled, the PR reference is valid, and the commit is merged (an ancestor of HEAD);
   - the old file is gone from HEAD **by path and by content**, so a move or a copy is rejected.

   If any record is invalid, the report credits nothing.

A baseline file deleted without a record stays in C and is listed as "missing without retirement".

Every modernization PR reports its LBR impact (`.github/pull_request_template.md`). A PR that only renames, moves, formats or wraps code reports **0 bytes retired**.

The baseline is frozen:
- `lbr.php verify` fails if `baseline.tsv` or `rules.tsv` no longer reproduces the inventory;
- `freeze` refuses to overwrite.

A scope change needs an explicit revision (`freeze --force-revision`, a new `revision=` number, and a documented reason in this file), reported next to the original B, never instead of it.

Tests: `dev/tests/lbr/run.sh` (32 checks, run in a throwaway clone, including relocation, unfrozen sets and separate reporting).
