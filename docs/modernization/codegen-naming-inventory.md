# Code generator: naming inventory and rename plan (issue #35, slice 1)

Issue: #35. This is an inventory and a proposal only: **nothing is renamed**. The proposed name, **Divengine Codegen** (CLI `divengine-codegen`), is a working proposal until the maintainer confirms it.

Scope: the PHP code generator historically called **cogePHP** ("C-oge O-tro GE-nerador para PHP", by Rafael Rodríguez Ramírez, 2010). It is **not** the MPI scheduling generator. The `generar()` SQL function, the `generador` schema and the `model/generator` PHP package all belong to the scheduling generator; they are out of scope here and belong to #21.

## 1. Inventory

### 1.1 Entrypoints and sources (`dev/`)

| Path | Role | Reads | Writes |
| --- | --- | --- | --- |
| `dev/cogephp.php` | Model generator: SQL scripts, `PartModel`, `XModel`/`X`/`XCollection`, `XDatabaseViews`, `XFunctions` | `dev/src/*.json` | `model/**` (and `$classpath` SQL scripts) |
| `dev/cogephpface.php` | UI/handler generator: combo, grid and gallery views and controllers, `add`/`set`/`del` handlers | `dev/src/*.json` | `view/{combo,grid,gallery}`, `control/view/{combo,gallery}`, `control/data/{add,set,del}` |
| `dev/cogephpservice.php` | Service generator | `dev/services/*.json` | `model/data/services/*Service.php` |
| `dev/crea_modelo_pg.php` | PostgreSQL introspector, database → JSON model | a database (`COGEPHP_DB_*`) | `dev/src/*.json` |
| `dev/cogephp.common.php` | Shared helpers: loader, naming, packages, type map | `dev/cogephp.conf` | — |
| `dev/cogephp.conf` | Configuration, mostly Áncora-specific (§2) | environment `COGEPHP_DB_HOST/PORT/USER/PASSWORD` | — |
| `dev/cogephp.sh`, `dev/cogephpface.sh`, `dev/crea_modelo_pg.sh`, `dev/*.bat` | Historical wrappers. **Destructive:** they `rm` the output folders (and `dev/src`) before generating; `chmod 0777` | — | — |
| `dev/path.php` | Include path for `import()` when run from `dev/` | — | — |

The generators must run with `dev/` as the working directory: every path is relative (`../lib`, `../model`, `../control`, `./src`).

### 1.2 Model inputs

- `dev/src/*.json`: 270 files. They carry the banner "cogePHP JSON (Sub)Model, generated by cogePHP Model Creator", written by `crea_modelo_pg.php`. These files are **provenance**: they record which tool produced them.
- `dev/services/*.json`: one example service (`service.example.json`), with the same banner.

### 1.3 Outputs

- 679 tracked generated files (`dev/ci/check-generated.sh`). **None of them contains the name cogePHP**, so renaming the generator changes no generated output, and the regeneration guard can verify that.
- Generated class names, `import()` package paths (`model.data.*`, `model.security.*`, `model.generator.*`, ...), JS event keys and SQL identifiers come from the database model. They do not come from the generator's name, and the rename must not touch them.

The following have **no** reference to the generator:
- Docker: `.dockerignore` is an allowlist that excludes `dev/` apart from `dev/sql/`, so no image contains the generator.
- `compose.yaml`, the e2e harnesses and the application runtime.

A hit for "coge" in `dev/sql/generador/generar.sql` is the Spanish verb ("se coge el primero"), not the tool.

## 2. Reusable logic and Áncora conventions

| Reusable (generic generator) | Áncora-specific (should become an "Áncora GOH profile") |
| --- | --- |
| JSON model loader; SQL type maps (`$mapa_type`, `$reverse_mapa_type`, `$entrecomillas`); naming helpers (`capitalLetter`, `getClassNameOf`, `fixFunctionName`) | `$projectname = "AncoraGOH"`, database name and user defaults, `$work_schema` (`public,matrix,util,prioriza,seguridad,portal,generador`) |
| Emitters: PartModel/Model/Item/Collection, function wrappers, services, `add`/`set`/`del` handlers, combo/grid/gallery | `$packages` (schema → `model.*` package), `$ignore_prefix_class_name`, `$ignora_columna`, `$foreign_key_descriptor`, `$table_desc`, `$titulos`, `$ortografia` (Spanish UI spelling) |
| Parameterized-SQL helpers (PR #36) | Output layout: `../model`, `../view/{combo,grid,gallery}`, `../control/{view,data}`, the `control/data/fdms/fdm_*.php` hook convention |
| PostgreSQL introspector | Runtime conventions in emitted code: the global `$dbconnection`, `import()` paths, `getReplica()` ids, `PasswordUtil` for `md5`-typed fields, Smarty-free `.tpl` includes |

Splitting along this line means:
- moving the right column into a profile file (for example `dev/codegen/profiles/ancoragoh.conf`);
- making output paths and runtime hooks profile settings.

That work can happen in place, without a new repository or framework. A second, unrelated synthetic schema generated with a minimal profile would prove the split before any extraction (#35, slice 5).

## 3. Proposed rename (after confirmation)

| Today | Proposed |
| --- | --- |
| `dev/cogephp.php`, `cogephpface.php`, `cogephpservice.php`, `crea_modelo_pg.php` | `dev/codegen/generate-model.php`, `generate-ui.php`, `generate-services.php`, `introspect-pg.php` |
| `dev/cogephp.common.php` | `dev/codegen/lib/common.php` |
| `dev/cogephp.conf` | `dev/codegen/profiles/ancoragoh.conf` (Áncora values) + defaults in `dev/codegen/lib/` |
| `dev/*.sh`, `dev/*.bat` (destructive) | one non-destructive CLI, `dev/codegen/divengine-codegen {model,ui,services,all,introspect,check}`, that resolves paths from the repository root instead of the working directory |
| `dev/ci/check-generated.sh`, `dev/ci/regenerate.sh` | `divengine-codegen check` / `divengine-codegen all`; the old scripts stay as one-line wrappers |
| `COGEPHP_DB_HOST/PORT/USER/PASSWORD` | `DIVENGINE_CODEGEN_DB_*`, falling back to `COGEPHP_DB_*` with a deprecation message |
| Banners written by the introspector | "Divengine Codegen (formerly cogePHP)" for new or refreshed JSON |

### Compatibility and safety

1. **One PR, two commits:**
   - a `git mv` of the files, so history follows them;
   - the reference updates (CI, docs, README).

   Generated outputs must not change: `check-generated` has to report 679 matches with **no** regenerated file in the diff.
2. **Shims.** Keep `dev/cogephp.php` etc. for one release as thin wrappers that print a deprecation line and `require` the new file. CI and contributors' commands keep working.
3. **Provenance.**
   - Do not rewrite the 270 JSON banners by hand; they change only when the model is refreshed with the introspector.
   - Keep the original header (author, year, original name) in the moved files, with a line "Originally cogePHP (2010)".
   - Historical commits are not rewritten.
4. **Out of scope.**
   - Database schemas, `generar()`/MPI functions, the `generador` schema and `model/generator`: these are #21.
   - Generated class and package names, and JS event keys.
5. **Checks after the rename:**
   - `check-generated`;
   - the codegen SQL tests (PR #36);
   - lint and the PHP 8.4 checks;
   - the HTTP e2e (`dev/e2e/run.sh`) and `docker/e2e.sh`, which must still place 8/8 with 0 collisions. Docker is unaffected, because the image never contains `dev/` apart from `dev/sql/`.

### Order with the other #35 slices

The rename touches the same files as the security, PHP 8 and reproducibility slices.
- To avoid conflicts, it should land **after** PR #36 and before the global English rename of #21. That way, #21 renames identifiers in already-moved files only once.
- Questions for the maintainer:
  - confirm the name;
  - confirm the CLI identifier `divengine-codegen`;
  - choose `dev/codegen/` versus a top-level `tools/codegen/`.
